# 确认标签后停留在启动训练界面 · 2026-10-26

## 用户现象

多角色图集预处理已完成，最后日志为“用户已检查标签并确认继续”，界面持续显示“已确认标签，正在启动训练引擎”，没有后续“正在启动 <引擎>”日志。截图未提供引擎启动日志，不能单凭等待时间归因到显存、模型读取或引擎缓存。

## 可复现原因

`ModernUIBridge.start_training` 的后台线程每 0.1 秒等待确认事件。旧实现中，`Event.wait` 返回超时之后、线程取得任务锁检查状态之前，用户可能执行 `continue_training`：状态变为 `running` 且事件被置位。旧线程仍执行超时分支，发现状态不再是 `awaiting_review`，直接返回。训练入口未被调用；finally 保存的状态仍为 `running`，因此 UI 没有后续进展。这是所有经该确认环节的模式共用的竞态。

## 复现与修复

`tests/test_training_review_handoff.py` 运行真实 bridge 训练后台线程，使用受控确认事件固定“超时返回与状态检查之间发生确认”的线程交错。预处理和引擎仅使用测试替身，不下载模型或调用 GPU。

- 修复前，多角色 MOSS 与普通 Qwen 训练均重现：线程退出、引擎调用 0 次、状态保留 running、日志停止在用户确认。
- 取消分支修复前后均不应启动引擎。
- 修复后，每次轮询在确认操作使用的同一任务锁下，一并检查任务身份、当前状态与事件是否已置位。即使刚刚超时，也接受有效确认；取消和替换任务继续退出。
- 重复确认被拒绝，引擎入口仅调用一次。

## 验证

- 定向三项用例从两项失败转为全部通过。
- 三项用例各重复 40 次，共 120 次，全部通过。
- 单元测试 247 项：246 通过、1 跳过。
- 语法检查与 diff 空白检查通过。
- 证据位于 `work/review-handoff-20261026/` 的 `before.log`、`after.log`、`repeated.log`、`unit-tests.log`。
