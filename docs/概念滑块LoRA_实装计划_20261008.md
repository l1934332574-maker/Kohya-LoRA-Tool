# 概念滑块 LoRA 实装计划

日期：2026-10-08  
状态：保留原始调查与设计，首版实现纳入 v0.19.2 发布批次；实施情况见文末及同目录的实现与验收记录。

## 1. 产品范围

独立训练目的，保留已确认的三种选择：双向变化 / 减少一种效果 / 增强一种效果。不提供年龄、服装等固定效果模板，由用户定义自己的变化。

- 双向变化：负权重往用户定义的负向变化，正权重往正向变化。
- 减少或增强：界面使用 0→1 强度，越大越接近所选目标；在训练目标与导出记录中明确方向。
- 所有目的的 0 都表示关闭该 LoRA、使用底模原本表现；不表示两侧图片的平均，也不表示自动还原某张原始照片。
- 首版交付训练、权重对照采样与 LoRA 导出。拖动已有照片即时编辑属于另一项功能。

## 3. 用户流程与 UI

入口：新建项目 → 选模型 / 版本 → 训练目的「概念滑块」→ 独立页面。界面显示能用的后端和原因，不要求新手识别引擎编号。

页面只保留四块：

1. **控制什么**：三个目的按钮；双向填写负向 / 正向，单向填写希望减少 / 增强的效果；作用对象可选。
2. **怎样定义**：默认文字；可切换对照图片。两侧图片支持拖放、选文件夹，同名自动配对，失败的配对给出列表；始终允许人工调整。
3. **先试还是正式练**：先试效果 / 正式训练 / 自定义。默认分辨率 512，参数显示实际值、方案差异与当前架构限制；学习率和步数需要真实试训后标定。
4. **效果对照**：固定提示词和种子，显示权重条带、历史检查点与打开输出位置。日志仍在原任务窗口。

中文目标可让已有 AI 助手帮助整理为训练描述，必须展示给用户确认；没有服务时可以手工编辑，不把 AI 接入作为开训必需条件。

### 文字路线

- 用户只需要描述目标；可选补充尽量不变的身份、画风、构图等。
- 工具生成中性描述、两端描述与保护上下文，让用户核对。
- 冻结底模作为教师，依据其不同条件预测形成训练方向，只更新 LoRA 参数。
- 少量试训先判断底模是否能表达这项变化。底模不理解目标时，提示改用图片对照；不凭自动生成描述承诺能学到新概念。
- 不要求用户预先上传训练图集，也不要求先生成并保存一大批图片。

### 图片路线

- 将相同人物、构图、画风下的目标变化组织为对照；差异很大的两组图不能自动当作严格成对数据。
- 6–8 对可作为初次准备建议。允许一对先试流程，明确材料少、泛化未验证；不沿用普通人物模式的最低图数门槛。
- 每对图片共享裁切、缩放及增强规则；一侧无法读取时整对报错。清晰度默认仅提醒，不能单侧过滤后错配。
- 专用配对清单记录两端、方向、训练/验证用途，不走普通模式的强绑定、独立去重和自动关键词清洗。
- 在有足够材料时留出整对验证；不能把同一对不同裁剪伪装成独立验证数据。
- 自动生成或编辑对照图放第二阶段：预览并确认后才能训练，生成失败或改变身份时允许换图。不能从一张任意图片保证自动得到合格对照。

## 4. 后端结构

增加 `training_kind=slider` 与单独的 `slider` 配置对象。旧项目缺少该字段时按普通训练处理，原有 mode / engine / base_type 保留原职责。

| 位置（拟新增或改造） | 职责 |
|---|---|
| `kohya_core/slider_project.py` | 目标、方向、材料、验证点、版本与参数的统一合同；生成开训计划、保存与导出 |
| `kohya_core/slider_dataset.py` | 配对、检查、材料摘要与缓存指纹；不修改源图 |
| `kohya_core/slider_training.py` | 主程序里的预检、环境选择、启动子进程、取消、阶段进度与结果记录；不导入 GPU 库 |
| `training_backends/sliders/` | 在所选训练环境运行的真实 GPU 训练代码：文字目标、视觉目标与模型适配层 |
| `modern_ui/src/components/SliderWorkspace.vue` | 独立页面、方向说明、材料确认与参数展示 |
| `modern_ui/src/components/SliderSampleStrip.vue` | 权重对照、检查点切换和查看原始采样条件 |
| 项目配置 / 模型能力表 / 主程序桥接 / 训练队列 / Agent | 共用同一开训计划；先分流滑块，再决定是否预处理；不落回普通 LoRA 流程 |
| 打包 spec / 安装资源 | 显式附带 GPU 后端脚本及版本清单；GPU 库留在训练环境，不打入桌面 UI 程序 |

候选适配接口：加载并冻结底模、编码条件、编码图片、准备噪声状态、预测模型目标、设置 LoRA 倍率、生成采样、导出权重。目标函数和模型差异封装在后端，界面不拼引擎专属命令。

优先调查复用已安装 Fizgig / 现有模型环境；独立后端脚本按版本管理，避免修改用户已有引擎源码。不因新增模式就强制重装全部训练环境。

## 5. 训练与导出的关键规则

- 文字方案借鉴 Concept Sliders 的冻结教师方向目标；视觉方案采用成对对照与正负倍率目标。只更新 LoRA，首版不训练文本编码器。
- SDXL adapter 区分 epsilon 与 v prediction；Anima adapter 单独处理 flow 时间、latent 形状、速度目标与条件编码。
- 低 rank、短试训、多上下文与保护约束作为起点；不宣称消除过拟合，也不宣称增加训练步数一定更好。
- 双向训练不能只训练正向再把负倍率称为已学会反向。减少 / 增强的正倍率语义在目标和导出记录中一致。
- 训练失败报告失败阶段；采样失败单独报告，禁止把已有旧图显示成本次结果。
- 优先导出该架构通用 safetensors LoRA，记录底模身份、网络结构、训练方向和已检查的倍率范围。实际加载兼容性以目标推理工具验收为准。
- 不能通过同时取反 LoRA 的两个低秩矩阵来翻转方向；如需符号转换应按该导出格式的乘积规则处理并核对。

## 6. 采样与验收

双向对照默认设计点：-1 / -0.5 / 0 / 0.5 / 1。单向对照默认设计点：0 / 0.25 / 0.5 / 0.75 / 1。这些是观察点，真实安全有效范围需要按模型和训练结果确认。

每组只改变 LoRA 倍率，固定底模、提示词、负面提示词、初始噪声、尺寸、采样器、步数和 CFG。0 倍率必须恢复无 LoRA 的底模表现；按所用计算路径的数值精度核对，不能将不同种子当作变化证据。

验收按：

1. 产物能够在目标推理工具加载，正负倍率命名 / 导出正确。
2. 0 的底模基线正确，采样切换后没有遗留倍率或 GPU 状态。
3. 在未参与训练的描述、种子或图对上查看变化，判断方向是否可重复、是否只是记住训练图片。
4. 同时看身份、构图、画风等非目标变化；不把低 loss 作为有效或不过拟合的证明。
5. 阶段、日志、停止与恢复可见，Agent 与手动入口产生相同配置。
6. 多个检查点可对比、选择导出；进程完成与效果达标分开显示。

以上是后续实施验收要求，本轮没有执行 GPU 试验或新增测试。

## 7. 开发顺序

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| A：算法与适配验证 | 先实现 SDXL 文字最小任务，对照原始方法；同时验证 Anima 标准架构的文字目标和倍率 / 导出路径 | 能观察固定条件下的方向变化，0 基线正确；不能只以生成了文件为完成 |
| B：首版完整链路 | 独立项目与页面、三个目的、模型能力限制、预检、任务窗口、权重对照和导出 | 新手无需辨认引擎编号；不支持的组合明确提示，旧普通项目仍可使用 |
| C：自有风格材料 | 人工 / 自动配对、图片目标、配对预处理、独立验证与检查点对比 | 不误配、不改写源图，变化与非目标影响可查看 |
| D：减少材料工作量 | 经确认的自动编辑图对、Agent 补问与执行、队列、恢复和更多模型 / 显卡 | 生成质量能检查；模型 / GPU 路径逐项开放 |

Anima 纳入 A 阶段调查，不一概排除，也不在实训前显示为稳定支持。40 层 / 2.9B 需要支持该结构的适配层，不能沿用当前 Fizgig 标准 28 层假设。AMD 普通 LoRA 已有路径不等于滑块目标已通过 AMD 验收。

## 8. 当前结论

可实施；主要新增工作是专用训练目标、模型适配、配对处理、方向一致的采样与导出。既有项目、环境、任务窗口和助手接口可以复用。先获得真实可检查的变化，再把交互包装完整，避免仅增加一个名称和 UI。
