# 已有 LoRA 追加训练与高分辨率精修

## 已定方案

同一条流程提供三个入口：

- 新版项目页：已有 LoRA 追加训练。
- 训练记录：从本次结果继续。
- 采样历史：从此检查点高清精修。

原计划可以全程 512px 跑完，再选效果好的检查点，以 768px、1024px 或其他 64 倍数分辨率独立追加训练。步数制引擎填写追加步数，轮数制引擎填写追加轮数；学习率默认继承，可在展开项调整。不承诺固定提速比例或精修效果。

## 数据与状态

追加训练继承可训练 LoRA 权重，重新创建优化器、调度器和计数；完整断点续训继续使用原接口。原 LoRA、旧项目及其输出不覆盖。

新建唯一名称的子项目，输出到独立目录。复制来源 LoRA，记录 SHA-256、来源项目、训练记录、采样名称和前后分辨率。单人输入保留原始尺寸的图片，并优先复制当前训练副本标签，缺失时读取原图同名标签；多角色同时复制角色、同框组及其图片和标签。历史记录没有逐轮数据集快照，因此数据读取的是当前磁盘内容，界面已明确说明。

目标训练副本从原图重新生成，新项目独立缓存。不会把已经缩小到 512px 的训练图片当作高清原图。已有学习区域单独保存，在预处理后按目标训练几何缩放；裁切比例变化会停止并要求重新检查。训练仍经过标签和学习区域确认阶段。

采样自动映射仅识别可以唯一对应的 Fizgig `prefix-e000006_...png` → `prefix-000006.safetensors` 或同名状态目录中的 `lora.safetensors`。检查点缺失、同名歧义、其他命名格式均要求手动选择；不使用最近修改时间猜权重。

## 引擎接入

- Fizgig v8.5.0 / v8.9.6：独立启动脚本，在 `FamilyLoRA.add_trainable` 之后、优化器之前加载。严格比较层名、形状和 alpha，要求全部模块加载成功。保留已安装引擎源码及身份校验。
- Kohya 与 musubi（Krea2 / FLUX.2）：原生 `network_weights`，独立启动脚本检查 LoRA 加载时的 missing / unexpected keys。
- AI Toolkit（Qwen / Z-Image / Krea2）：原生 `network.pretrained_lora_path`；该分支上游会跳过来源文件训练步数元数据恢复。额外校验可训练网络加载结果。
- 三种启动脚本均有 Windows spawn 保护，并在创建优化器前要求初始 LoRA 已加载；普通训练、完整状态续训不启用该加载脚本。
- 当前只接受各层 rank / alpha 一致、alpha 为整数、带 alpha 的 down/up 或 A/B 格式的普通 safetensors LoRA。不支持 LoKr、DoRA、缺少 alpha 的文件、滑块和视频入口。来源 LoRA 需要匹配原底模；同架构底模的版本差异不能仅靠权重形状证明。
- Qwen Fizgig 追加训练保留来源 rank / alpha 和用户设定学习率，不由预设重新覆盖；Krea2 AI Toolkit 的旧默认 rank 升档也不会改写来源 rank。

## 本轮检查范围

- Python 源码 AST 语法检查及两类生成启动脚本的编译检查通过。
- Vue TypeScript 检查与 Vite 前端构建通过。
- Git 空白检查通过。
- 发布前运行续训、MOSS 和训练界面的 56 项既有检查，以及 4 项追加训练检查。
- 使用实际 Fizgig FamilyLoRA 在 CPU 上加载初始权重并完成一步优化；未启动 GPU 训练，未验证完整训练画质、显存和耗时。

实际训练验收需要分别确认：选择的初始权重完整加载、训练前后权重变化、追加计数、目标分辨率缓存、单人与多角色输入、学习区域对齐，以及原产物不被覆盖。不能把上述源码检查当作 GPU 验收。
