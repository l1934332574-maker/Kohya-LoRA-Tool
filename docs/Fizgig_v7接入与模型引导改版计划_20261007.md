### 当前使用边界

- 本轮只接普通 LoRA。整模微调、LoKR、概念滑块入口继续暂缓。
- SDXL 和 Anima 的 Fizgig 路径保留上游实验性标记；不宣称训练效果已经验证。
- Klein 4B 仍走当前 Musubi 路径，Klein 9B 走 Fizgig；Anima 2.9B / 40 层走 Kohya。
- 新项目默认分辨率仍为 512；已有项目保存的分辨率不强制覆盖。
- 本批应用改动纳入 v0.19.1 发布；实际渠道状态以发布结果为准。引擎镜像上传范围只有固定上游源码、公开 tokenizer/config、清单与许可证，没有个人连接设置、密钥、日志、图集或模型权重。

以下保留原调查和设计，用于追踪设计依据；其中未完成的验收项目仍属于待验证目标。

## 一、目标与实施顺序

让用户先选模型和版本，工具再推荐适合当前电脑的训练引擎；AMD 用户使用同一入口，优先推荐已适配的 Fizgig 路径。引擎升级尽量通过国内镜像完成，失败时保留原环境和原项目。

| 顺序 | 工作 | 用户能看到的结果 |
|---|---|---|
| P0-1 | 固定新版源码、准备国内镜像和下载清单 | 能下载到同一个经过适配的版本，不追随上游 master |
| P0-2 | 改造版本识别、更新与回退 | 显示当前/目标版本、下载进度、失败原因及恢复入口 |
| P0-3 | 迁移现有四个 Fizgig 模式 | Krea 2、Klein 9B、Qwen-Image-2.1、H3 使用新版训练入口 |
| P1-1 | 接入 SDXL、Anima 标准架构 | 新模式完整具备模型准备、训练、保存和采样流程 |
| P1-2 | 建立能力表，重做导航与引导 | 每个模型一个入口，先选版本，再推荐引擎 |
| P2 | 滑块训练、LoKR、底模微调等扩展 | 单独设计和验收，按实际接入情况开放 |

界面信息结构和能力表可以在 P0 时同步准备；新的推荐入口在对应适配完成后开放。

## 三、国内镜像更新方案

### 3.1 固定版本清单

新增一份 Fizgig 发布清单，记录：

- 源码 tag、commit、兼容的最低工具版本。
- 每个下载文件的名称、大小、SHA256、来源、适用平台和用途。
- Python / torch / torchvision / ROCm / bitsandbytes 等依赖版本。
- 支持的模型版本、CLI 参数和缓存/续训兼容说明。

客户端只提示和安装“工具已经适配、镜像已经准备”的版本。上游又发新版时，可以显示消息，不直接让旧工具安装未知 CLI。

实际已同步的目录（下载器使用以下路径）：

```text
engine_sources/
  fizgig-v7.0.1.zip
  fizgig-v7.0.1.json
  fizgig-v7.0.1-NOTICE.md
  helpers/
    <family>/<固定 HF commit>/  # 分词器、配置和上游许可证
  rocm/                    # 复用已有固定 ROCm 包
```

源码镜像保存指定 tag 的原始快照，并保留上游许可证和第三方声明。用于国内路径或兼容性的补丁单独记录，不假装它们是上游原始源码。

### 3.2 不同文件的获取方式

| 文件类型 | 首选方式 | 回退与复用 |
|---|---|---|
| 引擎源码 | 工具魔搭仓库的固定版本包 | GitHub 加速来源，再官方源；所有来源必须对应清单中的同一制品 |
| AMD torch / ROCm / bitsandbytes | 已有魔搭固定包 | 官方匹配版本兜底；包名/平台/版本/hash 均检查 |
| 通用 Python 依赖 | 现有国内 PyPI 主源与备用源 | 配套版本约束，避免安装解析器顺带替换 GPU 环境 |
| NVIDIA GPU 依赖 | 优先复用合格的已有环境；准备国内固定包或确认可用来源 | 没有对应国内制品时明确显示官方源，不承诺全部国内化 |
| 底模、VAE、文本编码器 | 优先识别已有文件，其次可用的魔搭模型镜像 | 只下载缺项；按模型版本与格式检查，不仅按文件名匹配 |
| tokenizer / processor / 模型配置 | 预备国内快照与本地读取路径 | 避免大权重已下载，启动时又悄悄去境外拉小文件 |
| 采样加速模型 / LoRA | 标为“采样可选” | 按用户选择获取；不能当作训练必需项强制下载 |

**小文件也属于接入范围。**Anima 编码器会获取 tokenizer 与 T5 tokenizer；SDXL 单文件加载仍依赖外部配置仓库；Qwen 2.1 有 processor 文件。应把这些快照接到本地读取路径，而不是仅修改大模型下载链接。[S5、S7、S8]

### 3.3 下载体验

- 下载前列出缺项、预计下载量和保存位置；已有完整文件显示“已就绪”。
- 显示当前来源、当前文件、已下载量/总量、速度、取消与重试入口。
- 支持断点续传；切换来源时确认制品/大小/校验信息一致，不能把两个不同归档的字节拼到同一 `.part`。
- 下载完成必须验证 hash、归档结构或模型完整性。失败文件不计入“就绪”。
- 安装完成后清楚显示使用的源码版本、GPU 后端和新增占用；提供已完成缓存/旧备份的清理入口，不自动删除回退需要的文件。

## 四、升级与旧项目迁移

### 4.1 版本识别

当前 `_fizgig_source_current()` 只检查文件存在，不能准确识别版本；新版改为读取安装记录及关键文件验证。

记录至少包含：源码版本/commit、适配器版本、源码路径、环境路径、后端、依赖指纹、能力验证结果。旧安装无记录时按“旧版已安装，版本待识别”处理；不能因旧 marker 在新版消失就判定整个环境损坏。

### 4.2 更新流程

```text
检查训练/缓存/下载任务是否正在使用引擎
→ 读取已适配版本清单，检查空间与缺项
→ 下载到独立位置，校验源码
→ 检查现有环境是否可复用
→ 准备必要依赖及本地辅助文件
→ 完成该平台的入口与运行检查
→ 原子更新引擎激活记录
→ 显示结果和回退入口
```

上游 v7.0.1 Windows AMD 默认安装依赖仍与本工具固定版本相同（torch 2.12.0+rocm7.15.0a20260728、torchvision 0.27.0、对应 SDK 和 bitsandbytes），NVIDIA requirements 的 GPU 版本也保持一致；因此应先评估复用，不能每次升级都重装全部环境。[S10、S12]

**回退必须包含环境。**目前更新器先修改原 venv 的依赖，再校验新源码；仅备份源码不能保证完整恢复。新版规则：

- 已有环境完全符合需求且无需修改时可以复用。
- 需要修改与旧版冲突的依赖时，建立独立版本环境；原环境保留。
- Windows venv 建在最终路径，用激活记录选择版本；不把构建完成的 venv 随意移动到另一绝对路径。
- 新版准备失败，原版本仍可运行；运行后发现问题也可以回退源码与对应环境。
- 更新互斥锁在运行状态检查后获取，并重新检查占用，避免检查与更新之间启动训练。

### 4.3 数据、缓存与续训

- 保留原图、标签、配置、模型与训练输出。
- 新版缓存使用独立目录及指纹：模型版本、组件标识、分辨率/桶设置、caption、缓存格式版本。
- Klein 上游已明确改用 `klein9bdrv` 缓存架构，首次重建，不混用旧缓存。[S9]
- 其他模型只在已确认格式兼容时复用，不能统一默认全部重建或全部沿用。
- 原 v6.5.0 训练状态优先在对应旧版本中续训。新版能否精确续训需检查网络命名、优化器、EMA 和状态格式；未确认前不能默默加载。
- “使用旧 LoRA 权重开始一轮新训练”与“恢复原训练状态”分开表述。
- 旧项目不会因为显卡或推荐变化而自动换引擎。

## 五、统一训练适配器

保留现有对 GUI / 队列的函数入口，内部收敛到 Fizgig 适配器，避免再复制六套训练逻辑。

### 5.1 模式映射

| 当前/拟新增模式 | 上游 family | 接入阶段 |
|---|---|---|
| `krea2_fz` | `krea2` | P0 |
| `flux2_fz`（明确为 9B） | `klein` | P0 |
| `qwen21_fz` | `qwen_image21` | P0 |
| `h3_fz` | `minimax` | P0 |
| 新增 Anima Fizgig 标准架构模式 | `anima` | P1 |
| 新增 SDXL Fizgig 模式 | `sdxl` | P1 |

新增内部模式名称在实现时确定，并保留已有项目和调用方的旧 key。

### 5.2 适配范围

- 缓存：`families/cache.py --family ... --stage latents/text --model ...`。
- 训练：`families/train.py --family ... --dit ...`；H3 专项参数通过 `--family_option`，音频等缓存参数通过 `--aux` 映射。[S3、S4]
- 量化：旧 `--quantize_4bit` / `--quant_int8` 等选项迁到新版 `--precision`。不同 family 的可选范围不同；不能把旧 `fp8` 文本机械转成新版全局参数。Klein 已预量化 fp8 文件的加载行为单独说明。[S4、S9]
- 调度与预设：显式传入有效学习率、优化器、调度器、EMA、自适应学习率设置，避免新版默认 `constant` 等悄悄改变旧项目。
- 分辨率：所有模式新项目仍默认 **512**；引擎的桶约束、采样尺寸单独展示，用户可以调高。
- UI、日志、训练摘要共用最终生效配置；自动量化的最终决策由引擎输出回填，不能把“计划值”说成“已生效值”。
- 首轮不自动启用上游自动改 caption、额外 AI 服务或所有高级特性；沿用工具现有数据处理链。

### 5.3 采样必须作为完整接入项

用户此前已反馈采样无反应或崩溃，这次不能只把训练入口换好。

- 定义每个 family 的训练底模、预览底模/加速 LoRA、步数、CFG、负面提示词和依赖。
- Klein 明确区分 Base 训练文件与 Distilled 预览文件，实际所用文件在界面与日志中一致；若准备提供 Base 直接采样，应独立确认该路径。[S9]
- 显示步数输入折算后的真实触发 epoch；明确“首次预览”“训练中预览”“结束预览”是否开启，保存计划时即可看见规则。
- 采样依赖缺失时说明缺什么，提供准备或关闭采样选项，不能点开却静默不出图。
- 将“缓存、加载、训练、采样、保存”作为实时状态；Agent 启动训练也打开同一个训练监控界面。
- 预览失败是否能安全恢复训练由适配后的具体运行结果决定，不提前承诺一律不影响训练。

## 六、模型与引擎能力表

新增后端能力表作为导航、模型准备、参数页、Agent 和队列共用的数据来源。前端不再维护一套与后端脱节的支持说明。

记录维度：

```text
模型系列 + 具体版本/结构 + 引擎 + 引擎版本 + 平台/后端 + 训练目的
```

每项包含模型组件、辅助配置、量化选项、缓存规则、采样依赖、可用功能、实验性标记和推荐依据。

状态分开保存与显示：

- **支持情况**：已适配 / 实验性 / 待接入 / 不支持该结构。
- **环境情况**：未安装 / 待检查 / 已就绪 / 需要修复。
- **组件情况**：齐全 / 缺项 / 损坏或格式不匹配。
- **验证情况**：仅上游声明 / 已完成本工具对应平台验证。

不能把“未安装”等同于“不支持”；不能将 NVIDIA 测得的速度或显存下限写成 AMD 保证。GPU 检查按需异步执行，不在侧栏初始化时阻塞整个界面。

项目新增可迁移字段：模型系列、具体版本/结构、引擎、选用的引擎版本、训练目的、设备选择策略、配置版本号。旧项目根据现有 mode/base_type/components 转换，保存未知字段；无法确定的版本标待确认，不靠文件名猜定。

```text
环境与模型管理
```

模型入口展示该模型的项目和“新建训练”；点击模型不会自动替当前项目更改引擎。

### 7.2 新建训练流程

1. **选模型**：可以导入本地底模，优先根据权重信息识别；也可以直接选系列。
2. **选版本**：Klein 4B/9B；Qwen 的具体版本；Anima 的识别结构。只有一个适用版本时不增加多余步骤。
3. **选训练目的**：人物 / 画风 / 概念。滑块功能接好后再开放对应目的。
4. **查看推荐方案**：显卡、推荐引擎、推荐依据、实验性说明；“其他引擎”默认折叠。
5. **选数据并准备缺项**：自动复用组件，只下载缺项；标签不完整时进入既有处理流程。
6. **确认有效设置并训练**：默认 512，展示参数摘要、采样规则、输出位置。

识别显卡失败时提供手动选择；多显卡显示名称与显存，让用户指定训练设备。

### 7.3 AMD 统一入口

统一入口体现为推荐和准备流程：

- 支持的模型/版本，优先推荐已经适配并符合该显卡条件的 Fizgig Windows ROCm 路径。
- 仍显示同一套模型目录；不做另一份容易失去同步的“AMD 专属模型菜单”。
- 4B 项目不能自动变成 9B；2.9B Anima 不能自动路由到固定 28 层的 Fizgig。
- 未适配的模型保留原路径和支持说明，不能因为 AMD 首选引擎不覆盖就隐藏全部模型。
- 兼容设置由所选后端统一管理，设置页保留手动覆盖，并记录修改原因。

### 7.4 推荐卡片和引导文案

推荐卡片示意（状态为说明格式，实际数据来自检查）：

```text
Krea 2 · 普通 LoRA
设备：AMD RX 7900 XT · 20GB
推荐：Fizgig · ROCm
原因：已接入该模型的 AMD 训练路径
准备：环境待检查；模型组件缺 2 项

[检查并准备]  [查看其他引擎]
```

| 当前界面（Before） | 新界面（After） | 原因 |
|---|---|---|
| 第一/第二/第三/第四引擎分组 | 模型单入口，版本先选择 | 新手无需先理解四套内核 |
| Krea2、Krea2AT、Krea2F | Krea 2；详情中比较训练引擎 | 避免像三个不同模型 |
| 模糊的 FLUX.2 标签 | 项目卡片明确 4B 或 9B | 防止组件和 LoRA 混用 |
| 安装第四引擎 | 准备 AMD / NVIDIA 训练环境 | 说明操作目的 |
| 固定四步检查项 | 完成项收起，当前缺项展开 | 让用户知道下一步 |
| 散落的支持说明和重复预设 | 从能力表与有效配置生成说明 | 减少文案与实际行为不一致 |
| 无理由的“推荐” | 展示推荐依据与验证状态 | 不虚构质量/速度排名 |

不同引擎比较显示：可训练目的、量化、采样、平台、验证状态、环境是否就绪与缺项。已安装可用环境可以作为推荐因素，但不是支持与否的判断。
