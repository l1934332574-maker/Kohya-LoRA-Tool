# Fizgig v8.9.6 接入与遮罩交互方案

更新：2026-10-25。引擎适配与下述遮罩功能已写入源码，前端已构建；尚未进行实际 CPU 分割、GPU 训练或安装包验收。

## 本轮接入

- 新项目默认选择 v8.9.6。项目已经保存的引擎版本保留；旧项目没有版本字段时仍按历史规则恢复版本。
- 兼容版本由后端提供，前端按模型展示。MOSS 保留 v8.5.0，Z-Image 保留 v7.3.1，其他原有兼容版本继续可选。
- 新版源码单独部署；旧版的本地配置补丁、源码签名和快照目录保持原来的版本身份。v8.9.6 使用上游的新 offloader，不再套用 v8.5.0 的 offloader 补丁。
- 匹配现有依赖时可复用 GPU 环境，不重复下载 torch / ROCm。遮罩生成的 LiteRT 暂未安装到用户环境。
- MOSS 新版允许本地选择 ComfyUI 的 INT8 / w4a8 GPTQ 文本编码器；旧版仍要求浮点编码器。默认下载仍是已有 BF16 文件，不替换用户文件。
- GPTQ 校验包含权重、格式描述、缩放、码本和分片完整性；根据本机实际 qwen3.5_9b_w4a8_gptq 文件头核对其 I8 打包权重和 F8_E4M3 相对缩放。尚未进行新版 GPU 编码/训练验收。
- 新版 MOSS 明确传入并记录上游 Clean-end 计划 `60:7:30:15:2`，把该计划写入续训身份，避免它在续训时悄悄改变。

## 遮罩入口：学习重点

放在“数据与训练方式”中、训练类型下方，不新增独立向导。默认整张图片，不改变已有训练任务。

| 主界面选项 | 行为 | 提示 |
| --- | --- | --- |
| 整张图片（默认） | 不启用遮罩 | 人物、物品、画风均可用 |
| 人物整体 | 使用 person 遮罩 | 更少学习背景；包含头发和服装 |
| 脸部与头发 | 使用 head 遮罩 | 更集中学习五官、发型；不保证保留服装 |

主区域只保留一个按钮：“生成并检查学习区域”。生成后原位置显示“已生成 28/30，2 张需要检查”，并提供“查看学习区域”和“处理 2 张问题图”。数字必须来自实际结果。

“更多设置”中再放：使用已有遮罩、身体与服装、排除脸部、替换自动生成的遮罩，以及背景参与程度。已有手绘遮罩不自动覆盖。

背景参与程度默认 10%，界面写“背景保留少量学习”，展开后可选忽略 / 少量（推荐）/ 较多。先不暴露阈值、羽化、膨胀等参数。

## 最短使用流程

1. 选择训练图片和学习重点。
2. 点击“生成并检查学习区域”；首次需要下载分割模型时，在同一任务窗口给出大小、进度、失败重试，不关闭窗口。
3. 在现有图集检查界面查看半透明高亮，可切换原图、学习区域、黑白遮罩。
4. 确认后继续原来的训练流程，自动带入遮罩参数。

不另做一套图集浏览器或模型管理窗口。重新预处理、改变裁剪和分辨率后，要明确标记原遮罩是否仍可复用。

## 多角色要特别处理

- 多角色模式下，“人物整体”更名为“所有角色”，说明每张图中的所有人物都参与学习。
- 单人素材按各角色目录生成；合照保留所有角色，并继续使用现有角色标签、位置描述和 DOP 设置。
- 遮罩只改变哪里计算训练误差，不能把不同人的身份自动分开，不能宣称它解决所有串脸问题。
- 首版不做“自动只保留指定角色”。如果照片里混入非目标人物，列入需检查素材；允许使用已有手绘遮罩或排除该图。现已提供简易画笔修正；参考脸匹配仍留待后续评估。
- 自动分割器面向真人，二次元、远景、小脸和遮挡的效果不能保证；必须让用户看高亮覆盖，不默认判定生成成功就正确。

## 数据和失败行为

- 遮罩按上游约定保存成 `photo-masklabel.png`，与处理后的 `photo.png` 配对。白色完全学习，灰色部分学习，黑色按背景参与程度学习。
- 优先在预处理完成后的项目训练副本生成遮罩，以免裁剪、EXIF 旋转和缩放造成错位。原图目录不改动。
- 导入原始遮罩时，必须复用原图的完整几何变换记录；不能只把遮罩拉伸到最后尺寸。多角色均衡复制图片时也复制其遮罩。
- 所有图集计数、图片预览、打标、去重和损坏图隔离均排除 masklabel 文件；导出时作为配对文件保留，不作为独立图片打标签。含遮罩的 WD14 图集使用同模型的内置 ONNX 路径，避免外部脚本重新扫描遮罩。
- 上游遇到缺失或无效遮罩会回退整图学习。软件要把缺失、尺寸错误、全黑、无法解码和覆盖异常分别列出，等待用户明确选择补生成、排除，或允许这些图片整图学习，不能静默回退。
- 已有手绘遮罩默认保留；重复操作只补缺失或已失效的自动遮罩。取消不留一个“看似完成”的文件，输出使用临时文件并原子替换。
- 训练报告记录实际有效/无效遮罩数量、生成器版本、mask_floor 和用户处理问题图的决定。续训身份包含遮罩内容散列与背景参与程度；改变遮罩后先提示与原训练不一致。

## 接入边界

首批只开放 v8.9.6 普通图片 LoRA 中已宣布支持的模型：Klein、Krea 2、Qwen Image 2.1、MOSS、Z-Image、SDXL、Anima。H3、视频、音频和概念滑块不显示入口。

首次生成时按需安装 `ai-edge-litert>=2.2,<3`，分割模型约 16 MB，CPU 执行。文件 SHA256 固定为 `c6748b1253a99067ef71f7e26ca71096cd449baefa8f101900ea23016507e0e0`。国内下载源需要单独准备和回读校验，不能把未经确认的镜像显示成可用。

## 已实现的使用流程

1. 新建或打开兼容图片项目，选择 Fizgig v8.9.6；旧版本需要先明确切换并配置环境。
2. 在“学习重点”选择人物整体、所有角色或脸部与头发。默认仍为整图；已有遮罩等选项放在“更多设置”。
3. 点击“打开遮罩编辑器”，先保存项目当前设置，再打开独立的大面板。左侧缩略图、中央画布、右侧自动识别与图片处理；无训练副本时可从面板内启动预处理和批量自动识别。
4. 默认原图叠加绿色学习区域，支持画笔 / 擦除、大小、透明度、缩放、拖动、撤销、全选 / 清空、保存并下一张；切图和关闭前保护未保存修改。自动识别使用项目保存的学习重点，保留手绘；详细日志折叠。下载失败仍能从空白遮罩开始手绘。问题图可排除或明确允许整图学习。
5. 首次自动生成按需准备 CPU LiteRT；分割模型先按系统网络设置下载，再尝试直连，每次校验固定 SHA256。本地 tflite 导入也校验固定散列；已检查好的区域直接进入确认，不要求下载自动模型。
6. 开始训练仍经过预处理后的确认环节。继续前重新检查遮罩；训练适配器再次检查并创建隔离的训练副本，再传入 `--masked_training --mask_floor`。

### 保存与兼容

- 原图及原始遮罩只读取。手工编辑、自动生成及已有遮罩导入均写入项目训练副本。
- `.loss_masks.json` 记录来源、生成器 SHA256、图片与遮罩散列及显式处理决定。图片内容改变后，旧的整图学习 / 排除决定须重新确认；自动遮罩切换学习重点后须重新生成。
- 多角色均衡副本同步应用手工修正和处理决定。标签修改导致预处理文件改名时，按图片内容与组别找回旧遮罩；图片本身改变时不套用旧区域。
- 切回整图时将遮罩移入 `.inactive_loss_masks`，恢复开启时再取回；旧引擎不应把这些遮罩识别成训练图。
- `mask_training/reviewed_*` 保存检查后的训练副本；只有内容与文件清单仍匹配时复用。输出目录的 `*.loss-masks.json` 保存本次实际清单；续训身份包含遮罩内容指纹、学习重点及背景参与程度。
- 打包清单已加入独立进程所需的 `loss_masks.py` 与 `loss_mask_worker.py`，避免冻结版缺少源码辅助模块。
- 本轮没有加入自动“只保留指定角色”的参考脸匹配。多人模式使用所有角色区域，身份归属仍依赖数据与标签。

## 2026-10-25 二次元分割与真人输入修正

- `mask_source=anime|photo` 为项目参数，手动选择；旧项目默认 photo，保留用户已有选择。学习重点选择和编辑器内均提供入口；编辑器中的变更保存后同步刷新工作区。
- Anime Segmentation 的作者 ONNX 文件为 176069933 字节（约 168 MiB）；固定提交、SHA256，CPU ONNX Runtime。RGB/255，长边缩放到 1024，中心零补边，预测后去除补边并恢复训练图尺寸。只自动分割人物前景，不宣称区分脸、头发或角色身份。
- 官方真人 TFLite 的内嵌 NormalizationOptions 实测为 mean=[127.5]、std=[127.5]。旧上游封装用了 RGB/255，现改为 (RGB-127.5)/127.5；本工具工作进程独立实现该输入处理，不改写用户的引擎源码。
- 生成器身份包含模型 hash 和推理版本。旧归一化生成的自动结果、或切换模型后的自动结果必须更新；手绘和外部修正保留。覆盖自动结果前备份旧文件。
- 编辑器显示名改成“学习区域预览 / 遮罩灰度图”；有效计数明确为格式检查通过，增加低权重提醒。遮罩与标签用途不同，界面明确提示仍需打标。
