# 界面性能与内置更新修复

日期：2026-10-25。版本：v0.19.18。

## 已复现的问题与处理

- `get_mode_workspace` 打开一个现有 Anima 项目时，运行完整 `fizgig_engine_status`，包含独立解释器导入 torch/GPU 探测。实测约 4.90 秒，其中此探测约 4 秒。导航改为检查当前项目指定版本的安装文件；实际训练仍由训练进程加载运行环境。修改后冷调用约 0.83 秒。没有验证所有模型和所有机器。
- 独立小工具先创建完整的隐藏经典工作区，包含重复建立项目主页。仅 `App` 初始化实测约 4.33 秒。工具入口改为轻量 Tk owner，只构建小工具本身，初始化约 0.22 秒。此数字不包含 Python 导入和后续工具面板首帧。
- 小工具 transient 指向隐藏 root，未做独立窗口的前置交接。工具弹窗解除隐藏 owner 的 transient 关系，首次显示 lift/focus；bridge 将前置权限交给子进程，同一工具重复点击复用已有进程。词典挂在可见小工具窗口上，不挂隐藏根窗口。
- 词典采用 40 个 CTk 结果卡片，单次查询触发大量 Canvas 重绘。改为单个原生表格，保留双击复制/插入、右键菜单、分类、排序和标签篮；逐项按钮改为所选条目操作。测量输入 blue、蓝发、hair、长发时，从约 0.8～3.4 秒下降到约 0～0.012 秒。词典首次开窗仍有构建开销，不宣称秒开。
- Windows 字体枚举原先每个控件都会执行，改为缓存进程内字体族选择，仍按调用动态使用字号。

## 更新缺失 JS/CSS

用户截图确认 `index.html` 引用的两项哈希资源不存在或不可读取。缺少受影响机器的安装日志，不能仅凭截图确定是安装被中断、占用、拦截还是安装路径不一致。

- 冻结程序启动更新时，传入当前 EXE 所在目录 `/DIR`，并在数据目录保存独立的安装日志。
- 在 EXE 的 PYZ 内嵌当前完整前端归档与 SHA256。启动时校验安装目录的资源及构建身份；缺失、内容损坏、旧新混用时，从 EXE 离线恢复到当前构建专属缓存。
- 恢复在临时目录完整校验后再发布，不改写正被其他实例使用的安装目录。不包含用户配置、项目、模型或训练数据。
- 隔离回放：删除 JS/CSS 后旧检查稳定报同类错误，新恢复路径通过（约 0.34 秒）；损坏缓存、混用旧首页的情形也能恢复。不代表已经在那十余位用户的机器上复现安装失败。
- 增加打包程序 `--check-ui-resources <report.json>` 诊断入口，供发布前对真实 EXE 做完整性与恢复检查。

## 验证边界

此记录中的时间来自本机独立诊断进程，不是所有用户的性能承诺。未关闭或改写用户正在使用的项目和工具进程。旧构建仍需取得包含修复的新安装包，旧 EXE 本身不会凭空获得恢复能力。


## 打包后检查结果

- 本地 v0.19.18 已完成前端构建、PyInstaller、Inno Setup 与便携 ZIP 生成，源码及包内容的隐私检查通过。
- 对真实打包 EXE 执行资源诊断：完整页面通过；暂时移走 JS/CSS 后从 EXE 离线恢复通过；还原后重新使用安装目录资源通过。所移动文件均在 finally 中恢复，并核对原 SHA256。
- 原生窗口检查通过：可见主窗口与工具子进程关联正确，工具的 Z 序位于主窗口上方；重复点击复用 PID。独立进程首次工具窗口可见约 2.7 秒，不能把 0.22 秒的构造耗时当作完整启动耗时。
- 上述包尚未上传发布。未在受影响用户机器复现整个升级过程，也未在本机覆盖安装正在使用的软件；没有关闭用户现有的工具进程。诊断过程中打开的独立探测进程已清理。
