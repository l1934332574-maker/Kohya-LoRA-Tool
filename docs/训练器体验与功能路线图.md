# 训练器体验与功能路线图

更新日期：2026-10-03。体验与采样规则改动分别纳入 v0.18.14 与 v0.18.15；各项实际边界和后续验证要求仍见下表。

## 产品目标

让用户能够选好数据、理解本次设置、观察训练效果、找回实验并继续训练。先改善这一整条流程，再进行大规模内部拆分。安装包黑屏反馈按用户要求暂缓。

## v0.18.15 后续体验与采样改动

按用户确认的顺序实施六档训练方案、差异确认与撤销、参数说明、生效设置摘要、固定采样种子、当前任务图库/对比、轻量反馈导出及原图/处理后图片检查。具体变更与实训边界见 `训练方案与采样体验_实施清单_20261003.md`。

这些源码功能已接线，不表示所有模型的采样已通过真实显卡验收。旧版黑屏仍暂缓；本轮按 v0.18.15 发布；未下载模型或启动 GPU 训练。

## 为什么先做采样和续训

先确保采样确实生成、失败原因可见且不会无故中断训练，再做图库与对比；否则新窗口只会展示空白或旧图。采样对比让用户判断是否学到目标特征；快照管理让长时间训练可以找回、延续或重新选择训练阶段。两者直接补足“训练进行中”和“训练结束后”的使用流程，优先于仅增加更多参数输入框。

## 验证范围

使用现有训练入口的模拟回归检查、参数与存储行为检查、前端类型构建和浏览器布局检查。浏览器曲线及历史详情检查使用明确标识的合成数据；没有进行 GPU 实训、真实大模型下载或安装包打包。

## 参数与界面文案核对（2026-10-02，本地改动）

统一规则：用户手填的正整数应按界面标出的单位直接传给引擎；`0`、留空、自动档必须说明所用预设；启动确认页应显示本次实际选择与无法准确预估的部分。模型采样可能发生在开始阶段，所以“每 N 步/轮”描述的是定期采样，不承诺首张图恰好在 N。

| 项目 | 已核对并修正 | 仍需按引擎验证 |
| --- | --- | --- |
| 采样/保存单位 | Qwen-Image-2.1、Fizgig H3 现标「轮」；Kohya、AI Toolkit 按「步」；Krea2/FLUX.2 的 musubi 保存按「轮」、采样按「步」 | 引擎版本更新后，需核对 CLI 参数和实际产物名称 |
| 手填采样间隔 | Kohya 与 musubi 的 1–9 步不再暗中回退；Fizgig 输入大于总轮数时不再暗中夹到总轮数 | 极短间隔带来的显存/耗时风险，以及开头是否立即采样 |
| 自动采样间隔 | Kohya、musubi 跟随保存节奏；AI Toolkit 每 250 步；Fizgig 按图集估算，H3 项目预设目前为 5 轮 | 预处理后可用样本与批大小会改变每轮步数；确认页暂不编造精确步数 |
| 开关与依赖 | 新版确认页展示自动/手动/快跑档结果，Krea2 Fizgig 缺少 Turbo 时明确提示本次无图；经典版取消“低显存自动关闭”误导 | 实际预览还可能因模型、显存或引擎异常失败，须在对应设备上验证 |
| 预览窗口 | 只显示当前项目任务的新图片；H3 视频和音频产物需看输出目录 | 多模态缩略图与可播放预览尚未统一 |
| 其他高影响文案 | 修订一键训练并非所有模式都运行 WD14、默认提示词因模式而异、分辨率越高不保证质量最好、不同模式训练步数上限不同、快跑档自动条件 | 继续核对量化、块交换、预热、保存/续训、标签覆盖等字段，显示引擎最终生效值 |

下一步宜把每个参数的“界面输入 → 预处理后的生效值 → 训练命令或 YAML → 日志/产物”作为同一条记录展示。这样能区分用户设置、自动适配和引擎自行降级；本批只覆盖高风险文案与采样间隔，不能据此判定所有模式的采样已能稳定出图。
